# JSON Examples: LLM-Extracted Clause Data

This directory contains two complete examples of LLM-extracted and annotated depositions from medieval inquisition trial registers. These JSON files represent the raw output of the extraction process using Claude Sonnet 4.5 with the extraction prompt (`extraction_prompt.txt` in parent directory).

## Files

### T14-001_extraction.json
**Deposition from Parnac Register**

- **Deponent**: Guillelmus de Moleriis, priest
- **Date**: 31 May 1273 (pridie kalendas Iunii)
- **Register**: Parnac (Toulouse Inquisition, 1273-1282)
- **Total clauses**: 95 clauses (c1-c95)
- **Content focus**: Testimony about brother Bernardus Bonus Panis and his heretical beliefs

**Key features demonstrated:**
- Trial procedural framing (ta.ed, ta.lp): Date, witness sworn, inquisitor named
- Complex question-answer sequences with nested subordination
- Multiple levels of reported speech (e.g., "Witness said that Bernardus said that...")
- Socio-theological belief content (rb.st): "No salvation except in heretical state", "Roman church not true church"
- Socio-moral belief content (rb.sm): "Church has only pride", "Death by fire is beautiful"
- Heresy/orthodoxy status judgments (ho): "He believes X is a heretic"
- Question tracking with response types (qr field): affirmation (af), denial (dn), elaborated answer (ea)
- NISI constructions elaborated to positive claims (e.g., c30-c31, c36-c37, c48-c49, c51-c52)

### T77-01-005_extraction.json

- **Date**: 14 October 1296 (indiction 9)

## Structure

Each JSON file contains three main sections:

### 1. Meta (Abbreviation Dictionary)
```json
"meta": {
  "abbrev": {
    "sy:syntactic_type": ["M:main", "CS:content_sub", "RS:relative_sub", "CC:circumstantial_sub"],
    "temp": ["t:testimony", "r:reported", "f:future", "g:general"],
    "act": ["a:actual", "n:non-actual", "h:hypothetical", "u:unclear"],
    "pol": ["+:positive", "-:negative"],
    "NT": { ... },
    "CT": [ ... ],
    "nag": [ ... ],
    "iag": [ ... ],
    "qr": [ ... ]
  }
}
```

This section provides the complete coding schema with abbreviations for all variables used in the clause annotations.

### 2. C (Clause Array)
```json
"C": [
  {
    "id": "c1",
    "sy": "M",
    "lat": "Latin text with subordinate clause IDs in brackets",
    "en": "English translation",
    "v": "verbal complex",
    "vt": "temporality",
    "va": "actuality",
    "vp": "polarity",
    "gv": "governing verbal complex",
    "g": "governing clause ID",
    "l": "embedding level (0=main, 1=subordinate, 2=doubly subordinate, etc.)",
    "NT": "narrative_type.subcategory",
    "CT": ["content_topic", ...] or "NA",
    "nag": "narrative_agency",
    "iag": "immediate_agency",
    "qr": ["clause_id.response_type", ...],
    "qre": ["clause_id.response_type", ...]
  },
  ...
]
```

Each clause object contains:
- **Structural information**: id, syntactic type (sy), hierarchical relationships (g, gv, l)
- **Text**: Original Latin (lat) and English translation (en)
- **Verbal complex**: The verb/verb phrase (v) with its temporality (vt), actuality (va), and polarity (vp)
- **Classifications**: Narrative type (NT), Content topics (CT), Agencies (nag, iag)
- **Semantic relations**: Question-response tracking (qr, qre)

**Note on hierarchical structure**: The `lat` field shows the Latin text with subordinate clauses represented as `[c#]` where the actual text of that clause appears in its own clause object. This preserves the hierarchical structure while avoiding text duplication.

### 3. N (Notes)
```json
"N": {
  "amb": ["Ambiguities and interpretive choices"],
  "alt": ["Alternative plausible segmentations or classifications"]
}
```

Documents ambiguous cases and interpretive decisions made during extraction.

## Extraction Process

These files were generated by:
1. Feeding medieval Latin deposition text to Claude Sonnet 4.5
2. Using `extraction_prompt.txt` as the system prompt with detailed segmentation and classification rules
3. LLM performs clause segmentation according to verbal complex (vcx) principles
4. LLM classifies each clause along multiple dimensions (NT, CT, agency, etc.)
5. LLM tracks hierarchical relationships (subordination) and semantic relations (question-response)
6. Output validated and minimally corrected if needed

## Key Extraction Principles Demonstrated

### Clause Segmentation
- **One verbal complex per clause**: Each clause contains exactly one vcx
- **Reporting verbs separated**: "He said he believed X" → 3 clauses ("said", "believed", "X")
- **Question frames separated**: "Interrogatus si vidit" → 2 clauses ("Interrogatus", "vidit")
- **NISI constructions elaborated**: Negative constructions with "nisi" expanded to positive standalone clauses

### Classification
- **Narrative Type (NT)**: Based on verbal complex function
  - Communication verbs (dicere, interrogare, respondere) → co.* even when deeply embedded
  - Cognitive verbs (credere, scire, videre as perception) → cg.* even when deeply embedded
  - Other verbs in narration → nc (narrative content)
- **Content Topics (CT)**: Hierarchical and inclusive
  - Religious belief (rb) with subtypes: socio-moral (sm), socio-theological (st), theological (th)
  - Multiple topics possible per clause
  - NA for governing clauses whose content appears in subordinates
- **Agency**: Two independent dimensions
  - NAG (narrative agency): Whose discourse? (i=inquisitor, d=deponent, n=notary)
  - IAG (immediate agency): Who is the grammatical subject? (dep=deponent, inq=inquisitor, oth=other, gen=general)

### Question-Response Tracking
- Tracks which clauses respond to which questions
- Response types: ea (elaborated answer), af (affirmation), dn (denial), nk (no knowledge), pr (partial)
- Targets content clauses (CT ≠ NA), not communicative frames

## From JSON to CSV

The clause-level CSV dataset (`clauses.csv` in parent directory) is derived from these JSON files:
- Each clause object becomes one row
- The full Latin text (`lat`) and English translation (`en`) are **removed** for privacy/copyright
- Hierarchical structure (governed_by relationships) is **removed**
- All classification variables (v, vl, vt, va, NT, CT, nag, iag, qr) are **retained**
- Binary indicators created for each content topic (ct_rb, ct_rb.sm, ct_ra, etc.)

## Usage

These examples serve multiple purposes:
1. **Documentation**: Illustrate the complete extraction output format
2. **Validation**: Allow verification of extraction quality and consistency
3. **Training**: Examples for understanding the segmentation and classification system
4. **Comparison**: Show cross-register differences (Parnac vs. Bologna)

To understand how the extraction prompt produces these outputs, see `extraction_prompt.txt` in the parent directory.

## Example Clause

From T14-001_extraction.json (c30-c31 - NISI construction):

```json
{
  "id": "c30",
  "sy": "CS",
  "lat": "quod non erat salus in aliquo alio statu nisi in statu hæreticali",
  "en": "that there was no salvation in any other state except in the heretical state",
  "v": "erat",
  "vt": "g",
  "va": "n",
  "vp": "-",
  "gv": "dixit",
  "g": "c29",
  "l": "2",
  "NT": "nc",
  "CT": ["rb.st"],
  "nag": "d",
  "iag": "gen"
}
```

This clause demonstrates:
- **Negative polarity** (vp: "-") with NISI construction
- **General-time** temporality (vt: "g") - timeless claim
- **Non-actual** presentation (va: "n") - negated claim
- **Socio-theological belief** content (CT: rb.st) - about salvation efficacy
- **Deponent discourse** (nag: "d") - in deponent's narration
- **General subject** (iag: "gen") - abstract theological claim
- **Level 2 embedding** (l: "2") - subordinate to subordinate

Followed by the positive elaboration (c31) making explicit what "nisi" implies:
```json
{
  "id": "c31",
  "sy": "CS",
  "lat": "<erat> salus in statu hæreticali",
  "en": "there was salvation in the heretical state",
  "v": "<erat>",
  "vt": "g",
  "va": "a",
  "vp": "+",
  ...
}
```

This pair shows how the extraction prompt handles complex Latin constructions to make implicit claims explicit.
